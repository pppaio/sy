【1.1 需求拆解与设计思路（B角色：邻接矩阵）】
  必做5项功能：创建图、添加景点、添加路径、显示景区图、显示景点链表

  设计思路：
    ┌────────── SOLID原则在C工程中的落地 ──────────┐
    │  SRP 单一职责：每个模块只做一件事                │
    │     console_utils模块  → 输入输出辅助           │
    │     graph_matrix 模块 → 邻接矩阵数据存取        │
    │     graph_interface 层 → 抽象接口虚函数表        │
    │     main 主流程        → 声明式高层编排          │
    │  OCP 开闭原则：新增邻接表/十字链表不用改main      │
    │  LSP 里氏替换：GraphOps虚表任意实现均可互换      │
    │  ISP 接口隔离：读/写/展示接口分开最小粒度        │
    │  DIP 依赖倒置：main只include接口，不碰具体实现   │
    └──────────────────────────────────────────────┘
    设计模式组合：
      ① 策略模式 Strategy → GraphOps虚函数表封装"邻接矩阵策略"
      ② 工厂模式 Factory  → createAdjacencyMatrixGraph() 返回抽象IGraph*
      ③ 模板方法         → main的handleCreate/handleAdd流程可复用

【1.3 数据结构定义（PascalCase大驼峰命名：类型名）】
  // 顶点
  typedef struct {
      int  vertexId;
      char vertexName[MAX_VERTEX_NAME_LENGTH];   // 小驼峰：字段/变量/函数
      char vertexDesc[MAX_VERTEX_DESC_LENGTH];
  } GraphVertex;

  // 邻接矩阵具体实现（只在graph_matrix.c里可见，main不依赖）
  typedef struct {
      GraphVertex vertexTable[MAX_VERTEX_COUNT];
      int         weightMatrix[MAX_VERTEX_COUNT][MAX_VERTEX_COUNT];
      int         vertexCount;
      int         isDirected;
  } MatrixGraphImpl;

  // 策略模式虚函数表：10个接口
  typedef struct GraphOps {
      void (*createGraph)(IGraph*, int isDirected);
      void (*destroyGraph)(IGraph*);
      int  (*addVertex)(IGraph*, const char*, const char*);
      int  (*addEdge)(IGraph*, int, int, int);
      int  (*getVertexCount)(const IGraph*);
      int  (*getVertexById)(const IGraph*, int, GraphVertex*);
      int  (*hasEdge)(const IGraph*, int, int);
      int  (*getEdgeWeight)(const IGraph*, int, int);
      void (*displayGraph)(const IGraph*);
      void (*displayVertexList)(const IGraph*);
  } GraphOps;

  // 抽象句柄（main只知道这个，不知道MatrixGraphImpl）
  struct IGraph { const GraphOps *ops;  void *implData; };

【1.4 5项核心API伪代码（小驼峰camelCase）】

  ── createGraph(IGraph *self, int isDirected) ──────────
  impl ← self.implData as MatrixGraphImpl
  impl.vertexCount ← 0
  impl.isDirected  ← isDirected
  FOR row IN 0..MAX_VERTEX_COUNT-1:
      FOR col IN 0..MAX_VERTEX_COUNT-1:
          impl.weightMatrix[row][col] ← (row==col ? 0 : INF)

  ── addVertex(self, vertexName, vertexDesc) → int newId ─
  impl ← self.implData
  IF impl.vertexCount >= MAX THEN RETURN -1
  newId ← impl.vertexCount
  impl.vertexTable[newId].vertexId   ← newId
  impl.vertexTable[newId].vertexName ← safeCopy(vertexName)
  impl.vertexTable[newId].vertexDesc ← safeCopy(vertexDesc)
  impl.vertexCount ← +1
  RETURN newId

  ── addEdge(self, fromId, toId, edgeWeight) → int ──────
  IF fromId/toId 越界 OR edgeWeight<0: RETURN -1
  impl.weightMatrix[fromId][toId] ← edgeWeight
  IF self is 无向图:
      impl.weightMatrix[toId][fromId] ← edgeWeight  // 对称
  RETURN 0

  ── displayGraph(self) ─────────────────────────────────
  打印 图类型/顶点数/INF说明
  打印 表头行 V0:xxx V1:xxx ...
  FOR EACH row i:
      打印 "Vi:name"
      FOR EACH col j:
          w = weightMatrix[i][j]
          PRINT (w==INF ? "INF" : w)
      换行

  ── displayVertexList(self) ─────────────────────────────
  打印 [HEAD] → V0:xxx → V1:xxx → ... → [NULL]   // 全局链表头
  FOR EACH vertex i:
      打印 "顶点链表#i | Vi:name (desc)"
      打印 " 相邻: "
      FOR EACH j:
          IF i!=j AND weightMatrix[i][j]!=INF:
              PRINT "[Vj:name | weight] ->"
      空则 "(无相邻景点)"

【2.2 CMakeLists.txt（构建自动化，对应实验目的1-3）】
  cmake_minimum_required(VERSION 3.10)
  project(ScenicGraphMatrix C)
  set(CMAKE_C_STANDARD 11)
  include_directories(${PROJECT_SOURCE_DIR}/include)
  set(SOURCES src/graph_matrix.c src/console_utils.c src/main.c)
  add_executable(scenic_graph_matrix ${SOURCES})
  set_target_properties(... RUNTIME_OUTPUT_DIRECTORY build)

  构建命令：
    cmake -S . -B build       → 生成Makefile/VS工程
    cmake --build build        → 一键编译，原理：自动扫描依赖增量构建
  等价gcc手动：
    gcc -Iinclude -std=c11 -finput-charset=UTF-8 -fexec-charset=GBK \
        -o build/scenic_graph_matrix src/*.c   ← 方案A中文编译参数

四、实验总结
=============================================================================================

本次项目开发严格遵循指定 Git 分支管理策略、Commit 提交规范、驼峰命名规则；代码采用多文件模块化拆分，遵循声明式编程与 C 语言开发最佳实践，在设计时参考 SOLID 设计原则，保证代码低耦合、高可读性与可扩展性。开发全程使用功能分支独立开发，开发前同步基准分支，功能完成后标准化提交代码，最终合并至公共 feature 分支与 master 主分支，完成双人协同开发。

具体收获总结如下：

1. C工程化能力提升
   深刻体会到多文件开发的必要性：接口层graph_interface、实现层graph_matrix、工具层console_utils、编排层main四层分离，任一模块修改不会连锁导致其他模块大规模改动。CMake自动化构建免去手写gcc长命令之苦，-finput-charset/-fexec-charset解决Windows中文乱码痛点。

2. 数据结构理解加深
   通过实现B角色邻接矩阵，与A角色史哲南邻接表对比，彻底掌握了两种图存储的适用边界：
     • 邻接矩阵：O(1)判断边是否存在，适合景点数≤20的稠密景区图(本次场景)
     • 邻接表：O(V+E)空间，适合城市地铁网络图这类E远小于V²的稀疏图
   二维数组 + 结构体的组合运用、指针与void*句柄封装IGraph抽象的技巧，在本项目中得到实战锻炼。

3. SOLID原则在C语言中的落地
   以往SOLID只在Java/C++的OOP中听说，本次证明纯C也可以做到：
   • SRP：console_utils只管IO、graph_matrix只管数据、main只管流程
   • OCP：新增A角色邻接表，main.c零修改直接通过工厂模式切换
   • DIP：main只#include graph_interface.h，从未引用MatrixGraphImpl
   • 策略模式+工厂模式的组合，实现了"C语言中的多态"。

4. Git双人协作实战
   和史哲南同学在feature_whj / feature_szn两条个人分支并行开发，体验了完整的工作流：
   开发前同步feature → 功能分commit规范提交 → push个人分支 → 提PR合并到feature → 解决README冲突 → 最终合入master。特别是冲突解决环节，从害怕CONFLICT报错到能从容删标记、手工合并保留双方贡献，是本次最大成长点。

5. 代码可读性与工程规范
   从snake_case统一改为camelCase小驼峰(vertexId/edgeWeight/addVertex)，PascalCase大驼峰命名类型(GraphVertex/IGraph/GraphOps)，宏常量保持SCREAMING_SNAKE(INF/MAX_VERTEX_COUNT)。加上commit message严格type前缀，回看日志一目了然。

以上5个维度的收获远超"写一个邻接矩阵"的代码量本身，为后续大三软件工程、毕业设计、企业级项目协作打下了扎实基础。
